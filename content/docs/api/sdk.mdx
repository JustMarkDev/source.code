`sdk/typescript/index.ts` is one file with no dependencies. Copy it into a project, or import it from the repository. It uses `fetch`, so it runs in Node 18+, Bun, Deno and the browser.

```ts
import { createClient } from './sdk/typescript'

const sx = createClient({ token: process.env.SX_TOKEN })

const change = await sx.changes.get({ owner: 'dana', repo: 'gitfs', number: '216' })
if (change.actions?.land.allowed) {
  await sx.changes.land({ owner: 'dana', repo: 'gitfs', number: '216', body: { expected_tree: change.head.tree } })
}

for await (const issue of sx.paginate('issues.list', { owner: 'dana', repo: 'gitfs' })) {
  console.log(issue.number, issue.title)
}
```

Every operation is a method named like its id: `changes.land` is `sx.changes.land`, `webhooks.deliveries.list` is `sx.webhooks.deliveries.list`. Path and query parameters go flat in the first argument and the JSON body goes under `body`. The result is the object, already typed.

## It cannot drift

The types are generated from the same schemas the server validates responses against. `bun scripts/api-sdk.ts` rewrites the file, and a test fails if the committed file is not what the generator writes, so changing a schema without regenerating the client does not pass.

## What it does for you

| Behaviour | Detail |
| --- | --- |
| **Retries what is safe to repeat** | Reads, naturally idempotent writes, and any write it has given a key. It retries on network errors, `502`, `503`, `504` and anything the server marks `retryable`, up to 3 times, waiting `Retry-After` when there is one and otherwise backing off from 250 ms. Not on a `4xx` that cannot help. |
| **Makes writes repeat-safe** | A write that is not naturally idempotent gets an `Idempotency-Key`, and every retry sends the same one, so a lost response never creates two issues. Pass your own with `{ idempotencyKey }`. |
| **Caches by `ETag`** | A repeat `GET` sends `If-None-Match`; a `304` returns the object it already holds, and costs no rate-limit units. 500 entries by default; `cacheSize: 0` turns it off. |
| **Paginates** | `sx.paginate(id, input)` follows `next_cursor` until the list ends. |
| **Throws one error type** | `SxError` has `status`, `code`, `hint`, `retryable`, `exitCode`, `requestId` and the whole `problem`. Branch on `code`. |

## Request options

The second argument of every method:

```ts
await sx.changes.update(input, {
  ifMatch: change.version.toString(), // fail with version_mismatch if it moved
  dryRun: true,                       // check everything, change nothing
  idempotencyKey: 'my-key',
  wait: 20,                           // hold a conditional read until the object changes
  signal: AbortSignal.timeout(5000),
})
```

`sx.last` holds the headers of the latest response, for the rate limit and the request id. `account: 'northwind'` in `createClient` sends `Sx-Account` to act as an organization.

## Other languages

Any OpenAPI 3.1 generator can produce a client from [`/v1/openapi.json`](/docs/api/agents#learn-it-from-the-api). The `x-sx-*` members carry what a generator would otherwise guess: which operations are safe to retry, which accept `dry_run`, and which pool they spend.
