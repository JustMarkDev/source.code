### `changes.list`

`GET /repos/{owner}/{repo}/changes`

**Changes in a repository**

Open and draft changes by default, most recently updated first. Each change carries its checks and policy rollups, so one request is enough to show a list with CI and policy state.

| About      |                                            |
| ---------- | ------------------------------------------ |
| Safety     | `read`, safe to repeat                     |
| Needs      | nothing for public data, a token otherwise |
| Scopes     | `pulls:read`                               |
| Rate limit | `read` pool, 1 unit                        |
| Wait       | `?wait=20` with `If-None-Match`            |
| Fields     | `?fields=a,b.c`                            |
| Success    | `200`, a list of `change`                  |

**Path parameters**

| Name    | Type   | Notes |
| ------- | ------ | ----- |
| `owner` | string |       |
| `repo`  | string |       |

**Query parameters**

| Name     | Type                                                   | Notes                                                                                              |
| -------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| `limit`  | integer (min 1, max 200)                               | Default `50`. Items per page, 1 to 200. Larger values are clamped.                                 |
| `cursor` | string                                                 | `next_cursor` from the previous page, exactly as returned                                          |
| `state`  | string                                                 | Comma list. Default: open,draft                                                                    |
| `author` | string                                                 | Handle of the author                                                                               |
| `label`  | string                                                 | A label name                                                                                       |
| `branch` | string                                                 | The branch the change was made from                                                                |
| `sort`   | `-updated_at` or `updated_at` or `-number` or `number` | Default `"-updated_at"`.                                                                           |
| `expand` | string                                                 |                                                                                                    |
| `fields` | string                                                 | Comma list of fields to return, dotted for nested. `object` and `id` always stay.                  |
| `wait`   | integer (min 0, max 30)                                | With If-None-Match: hold the request up to this many seconds until the ETag would change. 0 to 30. |

### `changes.create`

`POST /repos/{owner}/{repo}/changes`

**Create a change from a branch**

Naturally idempotent: asking again for a branch that already has an open change adds a patch set, or returns the same change when the branch did not move. `Sx-Outcome` says which: created, patch_set_added or unchanged.

| About      |                         |
| ---------- | ----------------------- |
| Safety     | `write`, safe to repeat |
| Needs      | a token                 |
| Scopes     | `pulls:write`           |
| Rate limit | `write` pool, 1 unit    |
| Dry run    | `?dry_run=true`         |
| Success    | `201`, a `change`       |

**Path parameters**

| Name    | Type   | Notes |

| `owner` | string |       |
| `repo`  | string |       |

| Name      | Type    | Notes                                                                                                   |

`POST /repos/{owner}/{repo}/stacks/{stack}/land`

**Land a stack, bottom first**

Returns 202 and an operation. Children are rebased onto what landed and keep their approvals because their trees do not change. Send the tree you expect for each change, by number.

| About      |                                           |
| ---------- | ----------------------------------------- |
| Safety     | `destructive`, not safe to repeat blindly |
| Needs      | a token                                   |
| Scopes     | `pulls:merge`                             |
| Rate limit | `write` pool, 1 unit                      |
| Dry run    | `?dry_run=true`                           |
| Async      | answers `202` and an operation            |
| Success    | `202`, a `operation`                      |

**Path parameters**

| Name    | Type   | Notes |
| ------- | ------ | ----- |
| `owner` | string |       |
| `repo`  | string |       |
| `stack` | string |       |

**Query parameters**

| Name      | Type    | Notes                                                                                                   |
| --------- | ------- | ------------------------------------------------------------------------------------------------------- |
| `dry_run` | boolean | Run every check and change nothing. The answer is what would have been returned, with Sx-Dry-Run: true. |

**Request body**

| Member           | Type             | Notes     |
| ---------------- | ---------------- | --------- |
| `expected_trees` | object of string | Required. |

**Example**

```bash
curl -X POST "https://api.source.code/v1/repos/dana/stacky/stacks/stk_stacky000000000000/land" \
  -H "Authorization: Bearer $SX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"expected_trees":{"1":"1111111","2":"2222222","3":"3333333"}}'
```
