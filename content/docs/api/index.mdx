The source.code API is plain HTTP and JSON at `https://api.source.code/v1`. The `sx` command line and the MCP server are clients of it, with the caller's own token, so they can do no more than the token allows. The web app is meant to be the third: no second, private API behind the screens.

<Callout type="warn" title="Preview">
  The API runs today on sample data, in memory, so every endpoint, header and
  error in these docs is real and tested, but nothing you write is stored for
  good. Real accounts, tokens and storage arrive with the hosted service. [What
  is built and what is not](/docs/api/roadmap).
</Callout>

## Try it

Run the app (`bun run dev`) and call it. The sample tokens work only on your own machine; see [Authentication](/docs/api/authentication#sample-tokens).

```bash
export SX=http://localhost:3000/api/v1
export SX_TOKEN=sxp_dana_full_access_0001

curl "$SX/repos/dana/gitfs/context" -H "Authorization: Bearer $SX_TOKEN"
```

`context` returns the open changes and what blocks each one, open issues, a policy summary and the env schema, in one request. It is what an agent calls first.

## The shape of a response

Every object says what it is, where it lives and which version it is.

```json
{
  "object": "change",
  "id": "chg_01m6dqs9m0g7q74420",
  "number": 216,
  "url": "https://api.source.code/v1/repos/dana/gitfs/changes/216",
  "title": "Cache negative ref lookups",
  "state": "open",
  "checks": { "state": "pending", "passed": 0, "failed": 0, "pending": 1 },
  "policy": { "state": "blocked", "blocking": 2 },
  "actions": {
    "land": { "allowed": false, "reasons": ["policy:ci-evidence pending", "policy:findings fail"] }
  },
  "version": 1
}
```

(Trimmed. [The full object](/docs/api/reference/changes#changesget).) Two things to notice. `checks` and `policy` are on the change itself, so a list of changes with their CI and policy state is one request, not one per item. And `actions` answers "can I land this?" without reading the policy first.
