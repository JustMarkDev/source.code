Send a token in the `Authorization` header. Never in a URL.

```http
Authorization: Bearer sxp_…
```

Public data (public repositories, the OpenAPI document, the error list) needs no token. Everything else does. A private repository answers `404` to anyone who cannot see it, so its existence does not leak.

## Tokens

The prefix says what a token is, so secret scanners can find a leaked one and you can tell at a glance what you are holding.

| Prefix | Is                                                   | Lives                                         |
| ------ | ---------------------------------------------------- | --------------------------------------------- |
| `sxp_` | A person's personal token                            | 30, 60, 90 days or 1 year. Always expires.    |
| `sxb_` | A bot or agent installed on repositories             | Until revoked or expired. Scopes only shrink. |
| `sxr_` | A run token: one repository, one run                 | The length of the run                         |
| `sxo_` | An OAuth access token, from [OAuth](/docs/api/oauth) | 1 hour, renewed with a refresh token (`sxf_`) |

Tokens are stored as hashes and shown once. A token may be limited to named repositories. See [what an agent never gets](/docs/concepts/agents).

## Create, list and revoke

```bash
curl -X POST "$SX/tokens" -H "Authorization: Bearer $SX_TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"ci","scopes":["repo:read","pulls:read"],"expires_in_days":30,"repos":["dana/gitfs"]}'
```

The response is the only time `secret` is shown. It needs the `tokens:manage` scope. These rules hold, and are tested:

- **A token can never have a scope its creator lacks**, and never outlives a year.
- **A token limited to repositories can only create tokens limited to the same ones.**
- You can have 100 active tokens.
- `GET /v1/tokens` lists yours without secrets, with `last_used_at` (updated at most once a minute, so reading a token never becomes a write per request). `DELETE /v1/tokens/{id}` revokes at once: the next request with it is `401 token_revoked`.
- Someone else's token answers `404`, as if it did not exist.

Applications you have authorized with OAuth are listed at `GET /v1/authorizations`; revoking one ends every token it holds.

## Who a token is

```bash
curl $SX/auth/principal -H "Authorization: Bearer $SX_TOKEN"
```

It returns the login, the account the request acts as, the actor `class` (`human`, `agent`, `bot`), the scopes, the repositories the token is limited to, and when it expires. It is never rate limited, so call it whenever you are unsure.

## Scopes

| Scope             | Allows                                                                  |
| ----------------- | ----------------------------------------------------------------------- |
| `repo:read`       | Read repositories, mirrors, uploads                                     |
| `repo:write`      | Create repositories and mirrors, announce uploads                       |
| `issues:read`     | Read issues                                                             |
| `issues:comment`  | Comment on issues                                                       |
| `issues:write`    | Open, edit and close issues                                             |
| `pulls:read`      | Read changes, run policy simulations                                    |
| `pulls:comment`   | Review, comment, resolve and dismiss findings                           |
| `pulls:write`     | Create changes, add patch sets, report checks, attach evidence, abandon |
| `pulls:merge`     | Land a change or a stack                                                |
| `secrets:schema`  | Read names and kinds of environment variables, request a grant          |
| `secrets:write`   | Set variables, approve and revoke grants (people only)                  |
| `secrets:decrypt` | Read values, through a grant for agents. Never granted by OAuth         |
| `webhooks:read`   | Read webhooks and their deliveries                                      |
| `webhooks:write`  | Create, change, delete and replay webhooks                              |
| `tokens:manage`   | Create and revoke tokens and authorizations. Never granted by OAuth     |

`pulls:*` is the scope family for changes. The names match the ones shown in **Settings, Agents and tokens**.

Every operation lists its scopes in [the reference](/docs/api/reference/changes) and in the OpenAPI document (`x-sx-scopes`). A missing scope is `403 insufficient_scope`, and the body lists `required_scopes` and `token_scopes` so you can see the gap:

```json
{
  "code": "insufficient_scope",
  "detail": "This needs the pulls:write scope.",
  "required_scopes": ["pulls:write"],
  "token_scopes": ["issues:read", "issues:write", "repo:read"]
}
```

Scopes narrow what a token can do. They never widen what its owner may do: reading a private repository still needs access to it, and changing one needs a role there.

## Acting as an organization

One login covers you and every organization you belong to. By default a request acts as you. To act as an organization, send `Sx-Account`:

```bash
curl $SX/auth/principal -H "Authorization: Bearer $SX_TOKEN" -H "Sx-Account: northwind"
```

You must belong to it, otherwise `403 forbidden`. `GET /v1/accounts` lists every account you can act as and your role in each. This is the same as `sx -A northwind`.

## Agents are people with limits

An agent token has a `class` of `agent` or `bot`, and everything it writes is attributed that way. The rules do not change for it, they get stricter where it matters:

- It goes through the same [policies](/docs/concepts/policies) as anyone. An agent's approval never satisfies a rule that asks for a human.
- It cannot approve its own work: `403 human_required`. A person doing the same gets `403 forbidden`.
- Its scopes can be reduced while it is installed and never grown. To add one, remove the install and approve it again.
- It never sees a secret value. `secrets:decrypt` is separate from `secrets:schema` and is a grant, not a standing permission.

The `Sx-Agent` header is reserved: clients may send it, but this version does not record it. An actor's `class` (`human`, `agent` or `bot`) is what marks automation.

## Sample tokens

For local development only. They are in `src/lib/api/sample.ts` and work when you run the app yourself, or set `SX_API_SAMPLE_TOKENS=1`. A deployed preview refuses them, so nobody can write into shared sample data, and its OAuth page offers no sample accounts.

| Token                       | Is                                                | Try                                     |
| --------------------------- | ------------------------------------------------- | --------------------------------------- |
| `sxp_dana_full_access_0001` | dana, owner of the sample repositories            | Everything                              |
| `sxp_hollis_maintainer_02`  | hollis, a maintainer who can review and land      | Approve a change, then land it          |
| `sxb_fix_agent_scoped_03`   | An agent: reads, writes and comments, cannot land | Open a change; see `insufficient_scope` |
| `sxb_triage_bot_issues_04`  | A bot installed on `dana/gitfs` for issues only   | `403` on anything that is not an issue  |
| `sxp_dana_limited_repo_05`  | dana, limited to `dana/tinyqueue`                 | Read `dana/gitfs`, fail to write to it  |
| `sxp_dana_expired_token_06` | An expired token                                  | `401 token_expired`                     |
| `sxp_stranger_no_access_07` | Someone with no access to private repositories    | `404` on `dana/notes`                   |
