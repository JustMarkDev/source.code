## When output is JSON

Output is JSON when `--json` is passed or stdout is not a terminal. Otherwise it is short plain text. The JSON shape of a command does not change between the two: the text is derived from it.

## Errors

On failure `sx` prints one object to stderr in JSON mode, or two lines in text mode.

```json
{
  "error": {
    "code": "repo_unknown",
    "message": "Could not tell which repository you mean.",
    "hint": "Run inside a clone, pass -R owner/name, or set SX_REPO."
  }
}
```

`code` is stable and safe to branch on. `message` is for people. `hint` is the next thing to try.

## Exit codes

The `code` in an error is the API's `code`, and the exit code is the API's `exit_code`, so a script, `curl` and `sx` agree. [Every code](/docs/api/errors).

| Code | Meaning              | Example                                         |
| ---- | -------------------- | ----------------------------------------------- |
| `0`  | Success              |                                                 |
| `1`  | Something went wrong | An unexpected error                             |
| `2`  | You used it wrong    | Missing argument, unknown repository context    |
| `3`  | Not found            | `not_found`, `account_not_found`                |
| `4`  | Not signed in        | `unauthenticated`, `token_expired`              |
| `5`  | Blocked              | `policy_blocked`, `forbidden`, `insufficient_scope` |
| `6`  | Needs a human        | `human_required`, `grant_required`, `needs_human` |

## Dry runs

`--dry-run` reports what would happen and changes nothing. The JSON includes `"dryRun": true`.

## Debugging

Set `SX_DEBUG=1` to print a stack trace for an unexpected error.
