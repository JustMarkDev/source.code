  touch a real repository.

## 1. Install sx

```bash
bun add -g @source-code/cli
sx --version
```

See [Install](/docs/cli/install) for other ways.

## 2. Create a repository

```bash
sx repo create dana/notes --public
git clone git@source.code:dana/notes.git
cd notes
```

Running `sx repo create` twice is safe. The second call returns the repository that exists.

## 3. Push a branch and open a change

```bash
git switch -c fix-typos
git commit -am "Fix typos in the readme"
git push -u origin fix-typos
sx change create
```

`sx change create` asks nothing. The title is your last commit, the base is your default branch, and the branch is the one you are on. Run it again after another push and it adds a **patch set** to the same change.

## 4. See what stops it landing

```bash
sx change view
```

```text
#3  open  Fix typos in the readme
patch sets 1, 0 approval, ci pending
  blocked: ci/test is running
  blocked: needs 1 human approval
```

## 5. Land it

```bash
sx change land
```

If a policy blocks it, `sx` exits with code `5` and says which requirement is missing. See [Policies](/docs/concepts/policies).
