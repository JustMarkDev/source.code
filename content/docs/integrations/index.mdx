source.code does not host runners or agent machines. You bring the ones you like.

## Two places, no repeats

| Where                                 | What you do                                                      |
| ------------------------------------- | ---------------------------------------------------------------- |
| **Settings, Integrations**            | Connect or disconnect a service. This is where you authorize it. |
| **Repository settings, Integrations** | Turn a connected service on for that repository, and tune it.    |

To add a service from a repository, use **Add an integration**. It opens the same dialog.

## What you can connect

| Kind                    | Works today                      | Planned                                                       |
| ----------------------- | -------------------------------- | ------------------------------------------------------------- |
| Code review             | CodeRabbit, or your own reviewer | Greptile, Macroscope, Cursor Bugbot, Claude Code Review, Qodo |
| Runners                 | Blacksmith, or your own machines | Namespace, Depot, WarpBuild                                   |
| Agent environments      | T3 Code, boat.dev                | E2B, Daytona, Vercel Sandbox, Cloudflare Sandbox              |
| Secrets and config      | Varlock                          |                                                               |
| Planning and monitoring |                                  | Linear, Sentry                                                |

A planned service is listed so you can see what is coming. It cannot be connected yet.

**Your own reviewer** and **your own runners** work the same way: register them with a token, and they report through the API like any other. The reviewer can be any model or tool you run.

<Callout type="warn" title="What is verified">
  The list is of services that publish a way to use them from another host or
  from an agent. How each one reports results back is not documented for every
  vendor, so source.code treats results as comments and checks on a change.
  Connecting is a screen on sample data in this preview.
</Callout>

## Access

Each service asks for named access up front, shown before you connect. A service can be disconnected at any time. Disconnecting also turns it off in every repository.

## Settings per kind

- **Code review**: whether a high-severity finding blocks landing, and which changes are reviewed.
- **Runners**: the label that sends a job to the runner, and how many jobs run at once.
- **Agent environments**: the access an agent gets, and a spending limit per task.
- **Secrets and config**: which schema file to read and when to check it.
