Everything marked **built** runs, is covered by tests and is in these docs. Everything marked **designed** is a decision, not a feature: do not build on it yet.

## Built, on sample data

| Area                                        | What works                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Contract                                    | Objects, IDs, lists with keyset cursors, `fields`, `expand`, `ETag` and `304`, `ndjson`, one error shape, CORS, `HEAD`.                                                                                                                                                                                                                                                                   |
| Discovery                                   | `GET /v1`, the OpenAPI document, `/errors`, `/limits`, `/auth/principal`, `/status` (what the server measured of its own answers).                                                                                                                                                                                                                                                        |
| Sign-in                                     | [OAuth](/docs/api/oauth) (the 2.1 profile): authorization code with PKCE, device flow, refresh rotation with replay detection, dynamic registration, revocation, discovery documents, resource indicators. One token for the API and MCP.                                                                                                                                                 |
| Accounts                                    | Changing a handle (sign-in can, the API does not follow it yet).                                                                                                                                                                                                                                                                                                                          |
| Tokens                                      | Create, list, revoke. Scopes that can only shrink, repository limits, always expiring, secret shown once.                                                                                                                                                                                                                                                                                 |
| Accounts and repositories                   | List, read, create (repeat-safe), edit an account, create an organization, its members and roles, invitations by email, languages, licence and links on a repository, stars, contributors, `context`, `numbers`, [rename, transfer, edit, hide and delete](/docs/api/repositories) (the old address answers `308`), id addressing, private repositories answering `404`.                  |
| People                                      | Profiles counted from commits, reviews, changes, issues and releases, follows, the directory of people, and preferences for what a profile shows and how downloads pick a file.                                                                                                                                                                                                           |
| [Teams](/docs/api/repositories#teams)       | Groups in an organization that give people read or write access to chosen repositories, inside the organization or not.                                                                                                                                                                                                                                                                   |
| [Git data](/docs/api/repositories#git-data) | Directories (or every file under one), files (as JSON or raw bytes), history, one commit and its diff. Immutable by commit id.                                                                                                                                                                                                                                                            |
| [Runs](/docs/api/runs)                      | A bounded task for an agent with a short-lived token limited to one repository and a few scopes, progress notes, outcome, cancel. Everything it does is recorded as an agent.                                                                                                                                                                                                             |
| Changes                                     | List, read, create (repeat-safe), edit with `If-Match`, patch sets, comparing patch sets, reviews, line comments and threads, raising and resolving findings, checks, policy and simulation, land, abandon, restore, mark ready, landing a stack as an operation, evidence, the files of a patch set whole, a patch set from edited files, suggestions on findings, test cases on checks. |
| Issues                                      | List, read, open (repeat-safe), edit, assign, close. Labels with a colour; comments; images and recordings.                                                                                                                                                                                                                                                                               |
| Notifications                               | Each person's inbox, fed from events: assigned, mentioned, reviewed, failed checks, landed. Unread count, mark read, preferences by kind.                                                                                                                                                                                                                                                 |
| Releases                                    | Publish (repeat-safe by tag), channels, notes, files uploaded with the release and served from it, checksums, withdraw with a reason, download counts. A stable release tells the people who starred the repository.                                                                                                                                                                      |
| Pipelines                                   | Runs with their jobs, steps and each step's log; start a workflow, run again, cancel; runners claim queued jobs and report each step.                                                                                                                                                                                                                                                     |
| Policy rules                                | A repository's rules with modes (enforce, dry run, off), rules it writes itself (a required check, path owners, a size limit), what each held back, what a dry run would block, time-limited exceptions per person, the policy file.                                                                                                                                                      |
| Integrations                                | Connecting a service to an account (with a key kept as a hash), turning it on per repository, disconnecting everywhere at once.                                                                                                                                                                                                                                                           |
| Bots and automations                        | Bots an account owns, installing them on repositories, their scopes (shrink only while installed), tokens limited to where they are installed; automations per repository that start a run for their bot on an event, on a schedule (every hour, day or week) or by hand, which the bot picks up with its own token.                                                                      |
| Imports and linked accounts                 | Importing a repository (it remembers where it came from and pulls through a mirror), your imports, saying who you are on other hosts (recorded as unverified).                                                                                                                                                                                                                            |
| Insights and the dashboard                  | A repository's commits by week and by who wrote them, contributors, downloads by day, stars, issue and change counts. Your dashboard: what needs you, what moves without you, activity, health, mirrors, storage, downloads, your contributions.                                                                                                                                          |
| [Search](/docs/api/search)                  | Repositories, changes and issues, prefix and phrase, qualifiers, no result cap, visibility applied.                                                                                                                                                                                                                                                                                       |
| [Uploads](/docs/api/uploads)                | Signed one-time addresses, content checked against type, evidence on changes, sandboxed serving.                                                                                                                                                                                                                                                                                          |
| [Webhooks](/docs/api/webhooks)              | Signed (Standard Webhooks), retried for about 28 hours, replay of any range, redelivery, secret rotation, SSRF protection, auto-disable.                                                                                                                                                                                                                                                  |
| Mirrors, secrets                            | Mirrors list, add, sync, pause, remove. Environment names and kinds, which environments need each, when it was last rotated and by whom, ciphertext-only writes, named recipients (add, remove), expiring grants for agents, audited reads.                                                                                                                                               |
| Events                                      | The log, the stream with `Last-Event-ID`, `sync`, `wait`, operations.                                                                                                                                                                                                                                                                                                                     |
| Writes                                      | `Idempotency-Key`, `If-Match`, `expected_tree`, `dry_run`, batch.                                                                                                                                                                                                                                                                                                                         |
| Limits                                      | Pools, headers, `429`, leased shared counters (in memory, or on Convex across nodes), concurrency guard, free `304`.                                                                                                                                                                                                                                                                      |
| Clients                                     | The `sx` CLI and the MCP server call this API with the caller's token and are limited by its scopes. `sx auth login` uses the device flow. A generated, dependency-free [TypeScript client](/docs/api/sdk) with retries, `ETag` caching, repeat-safe writes and pagination.                                                                                                               |
| Format                                      | `Accept: text/markdown` on a change, an issue and the context ([agents](/docs/api/agents#ask-for-text)).                                                                                                                                                                                                                                                                                  |
| Stability                                   | OpenAPI snapshot with a build check that fails on non-additive changes.                                                                                                                                                                                                                                                                                                                   |
| Docs                                        | The [reference](/docs/api/reference/changes) and the error list are generated from the code and fail a test when they drift.                                                                                                                                                                                                                                                              |

## Designed, not built

The web app's screens are the measure of what is missing: each area below is needed by a screen that runs on sample data today.

| Area                   | What is missing                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Storage                | With `CONVEX_URL` set, the domain (accounts, repositories, changes, issues, teams, runs, webhooks, uploads, mirrors, events, tokens, OAuth state) is on Convex and every API server holds only caches. Without it, the preview runs on sample data in memory. Git data still comes from the fake store: the code.storage client is built behind a guard but not connected. |
| Shared state, the rest | Nothing left per node on Convex: rate limits, idempotency keys (marked in each write's own transaction), the event feed, tokens, OAuth state, webhook deliveries and the status page's health are shared. Each node keeps its own search index, built from Convex and kept current from the feed.                                                                          |
| Sign-in, the rest      | Email goes through Resend when `RESEND_API_KEY` and `MAIL_FROM` are set, and to the log otherwise. Sign-in with another provider. A settings page for tokens and authorizations.                                                                                                                                                                                           |
| Git data, more         | Branches and tags, compare, blame, archive, history of a path, and history beyond the newest 1,000 commits.                                                                                                                                                                                                                                                                |
| Accounts               | Changing a handle (sign-in can, the API does not follow it yet). Account preferences.                                                                                                                                                                                                                                                                                      |
| Repositories, more     | Forking. Listing public repositories by category. Languages and licence are sample values until git data is real. Audit log, usage.                                                                                                                                                                                                                                        |
| Review extras          | Commenting from a line in the diff itself. A reading guide written by an agent.                                                                                                                                                                                                                                                                                            |
| Runners                | A runner process of our own: one needs the code checked out, so it waits for git hosting. Choosing a commit to start a workflow on.                                                                                                                                                                                                                                        |
| Integrations, more     | Each service doing its work: reviewing, running jobs, opening environments. Today connecting records the choice and the key.                                                                                                                                                                                                                                               |
| Imports, more          | Signing in with other hosts, so a linked account is verified, its repositories can be listed, and its contributions counted. Mirrors that carry issues and changes.                                                                                                                                                                                                        |
| Agents, more           | Run logs, a bot's own page.                                                                                                                                                                                                                                                                                                                                                |
| Webhooks, more         | Account-level webhooks; a webhook for several repositories.                                                                                                                                                                                                                                                                                                                |
| Batch                  | An all-or-nothing batch within one repository.                                                                                                                                                                                                                                                                                                                             |
| Versions               | Pinning a token to the version current when it was created. `Deprecation` and `Sunset` headers when something is deprecated.                                                                                                                                                                                                                                               |
| Clients, more          | Client libraries for other languages.                                                                                                                                                                                                                                                                                                                                      |
| Insights               | Contributors, downloads over time, the share of work done by agents, and the dashboard's list of what needs you.                                                                                                                                                                                                                                                           |
| Operations             | A CDN in front of public reads. The status page measures one server; several need their measurements shared.                                                                                                                                                                                                                                                               |
