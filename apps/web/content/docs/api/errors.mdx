Every error is `application/problem+json` ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457)) with a few members of ours. The CLI prints the same object on stderr and the MCP server returns it as an `isError` result, so one parser handles all three.

```json
{
  "type": "https://source.code/docs/api/errors#policy_blocked",
  "title": "Policy blocked this",
  "status": 409,
  "code": "policy_blocked",
  "detail": "#216 cannot land: ci/test is running on tree 9c4d7e1; 1 open: F-2 from greptile.",
  "hint": "Stop and report the failed requirements. Do not work around the policy.",
  "retryable": false,
  "exit_code": 5,
  "request_id": "req_01m6v2nqt5fs5m8zb0",
  "requirements": [
    {
      "id": "ci-evidence",
      "state": "pending",
      "needs": { "check": "ci/test", "bound_to": "tree" }
    },
    { "id": "findings", "state": "fail", "needs": { "resolve": ["F-2"] } }
  ]
}
```

| Member       | Use it to                                                                                                                                                  |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `code`       | Branch on it. It is stable and documented below. `detail` and `hint` wording can change, `code` will not.                                                  |
| `detail`     | Show a person what happened, in this case.                                                                                                                 |
| `hint`       | Know the next thing to try. It is the same string `sx` prints.                                                                                             |
| `retryable`  | Decide whether to send the same request again. See below.                                                                                                  |
| `exit_code`  | Map to the CLI's exit codes: 2 usage, 3 not found, 4 not signed in, 5 blocked by policy or permission, 6 needs a person.                                   |
| `request_id` | Quote it when you ask us about a failure. It matches the `Sx-Request-Id` header.                                                                           |
| `errors`     | On a `400`: one entry per field with a JSON Pointer such as `/body/title`, a `code` and a `message`. Never the value you sent, since it might be a secret. |

Some codes add members: `required_scopes`, `requirements`, `current`, `retry_after_seconds`. Each is described under its code.

## Retrying

`retryable: true` means the same request, unchanged, may succeed later. It is the only thing a generic retry loop needs to read.

- **`429` and `503`** are retryable. Wait `Retry-After` seconds, then back off if it fails again.
- **`request_in_progress`** is retryable with the same `Idempotency-Key`.
- **`request_outcome_unknown`** is not: the first request with that key made its change, then stopped before it answered, and it will not run again. Read the object to see where it stands.
- **`policy_blocked`** is retryable only when nothing has failed and every unmet requirement is `pending`, meaning something automatic, like CI, will clear it. If any requirement has `fail`, it is a stop. Report it. Do not look for a way round.
- Everything else is not. Fix the request, or ask a person.

Reads and writes sent with an `Idempotency-Key` are safe to repeat. See [Writes](/docs/api/writes).

## Every code

`GET /v1/errors` returns this table as JSON, so a client or an agent can read it once.

## The request

### `invalid_request`

**400.** The request is not valid. Not retryable. CLI exit code 2.

Fix the fields listed in `errors[]` and send it again.

### `cursor_mismatch`

**400.** The cursor does not belong to this request. Not retryable. CLI exit code 2.

Start again without a cursor. A cursor only works with the filter and sort that produced it.

### `unsupported_version`

**400.** That API version is not supported. Not retryable. CLI exit code 2.

Omit `Sx-Version`, or use one listed in `GET /v1`.

### `method_not_allowed`

**405.** That method is not allowed here. Not retryable. CLI exit code 2.

The `Allow` header lists the methods this path accepts.

### `payload_too_large`

**413.** The body is too large. Not retryable. CLI exit code 2.

Bodies are limited to 1 MiB. Upload large files with `POST /v1/uploads`.

### `unsupported_media_type`

**415.** Unsupported media type. Not retryable. CLI exit code 2.

Set `Content-Type: application/json`.

## Who you are

### `unauthenticated`

**401.** Sign in required. Not retryable. CLI exit code 4.

Send `Authorization: Bearer <token>`. Create a token in Settings, Agents and tokens.

### `token_invalid`

**401.** The token is not valid. Not retryable. CLI exit code 4.

Check the token was copied whole. Tokens start with `sxp_`, `sxb_`, `sxr_` or `sxo_`.

### `token_expired`

**401.** The token has expired. Not retryable. CLI exit code 4.

Create a new token. Tokens always expire.

### `token_revoked`

**401.** The token was revoked. Not retryable. CLI exit code 4.

Create a new token, or sign in again. A revoked token never works again.

### `signature_invalid`

**403.** The signed link is not valid. Not retryable. CLI exit code 5.

Ask for a new upload link. They expire after an hour and work for one file.

### `insufficient_scope`

**403.** The token lacks a scope this needs. Not retryable. CLI exit code 5.

Create a token with the scopes in `required_scopes`. Scopes on an installed bot can shrink but never grow.

### `forbidden`

**403.** You may not do this. Not retryable. CLI exit code 5.

You can see this, but your role here does not allow the action.

### `human_required`

**403.** A person has to do this. Not retryable. CLI exit code 6.

Stop and ask a person. An agent cannot approve its own work.

### `grant_required`

**403.** This needs a grant from a person. Not retryable. CLI exit code 6.

Request a grant, ask a person to approve it, then retry. Grants are short and cover one environment.

## Where it is

### `not_found`

**404.** Not found. Not retryable. CLI exit code 3.

Check the path. Private things answer 404 to everyone who cannot see them. `GET /v1` lists the collections.

### `moved`

**308.** This was renamed. Not retryable. CLI exit code 3.

Follow `Location`. It keeps the method and body. Store the new address, or better, the id.

## State and policy

### `invalid_state`

**409.** The thing is not in a state that allows this. Not retryable. CLI exit code 2.

Read the object and check its actions map.

### `stale_head`

**409.** The change moved since you read it. Not retryable. CLI exit code 2.

Read the change again, check the new head, and send expected_tree for it.

### `parent_not_landed`

**409.** A change below this one in the stack has not landed. Not retryable. CLI exit code 5.

Land the stack with `POST /v1/repos/{owner}/{repo}/stacks/{stack}/land`, or land the parent first.

### `policy_blocked`

**409.** Policy blocked this. Not retryable. CLI exit code 5.

Stop and report the requirements. Do not work around the policy.

### `version_mismatch`

**412.** Someone changed this since you read it. Not retryable. CLI exit code 2.

The `current` object is in `current`. Merge your change into it and send `If-Match` with its ETag.

### `limit_reached`

**409.** You have reached a limit on how many of these you can have. Not retryable. CLI exit code 5.

Delete one you no longer need. `GET /v1/limits` lists the numbers.

### `upload_incomplete`

**409.** The file has not been uploaded yet. Not retryable. CLI exit code 2.

PUT the bytes to the `upload_url` from the upload, then use it.

## Retries

### `idempotency_key_reused`

**422.** This Idempotency-Key was used for a different request. Not retryable. CLI exit code 2.

Use a new key for a new request, or repeat the original request exactly.

### `request_in_progress`

**409.** A request with this Idempotency-Key is still running. Retryable. CLI exit code 1.

Wait for `Retry-After` and send the same request with the same key.

### `request_outcome_unknown`

**409.** The first request with this Idempotency-Key changed something, then lost its answer. Not retryable. CLI exit code 1.

Read the object to see where it stands. Use a new key only for a new request.

## Limits

### `rate_limited`

**429.** Rate limit reached. Retryable. CLI exit code 1.

Wait for `Retry-After` seconds. RateLimit headers on every response say how much is left.

### `concurrency_limited`

**429.** Too many requests in flight. Retryable. CLI exit code 1.

Wait for a running request to finish, or wait for `Retry-After`.

## Our side

### `backend_unavailable`

**503.** A service we depend on did not answer. Retryable. CLI exit code 1.

Retry after `Retry-After` seconds with backoff. Reads and keyed writes are safe to repeat.

### `internal`

**500.** Something broke on our side. Not retryable. CLI exit code 1.

This is a bug. Quote `request_id` when you report it.
