A script you write today should still run in three years. The promise is simple, and the build enforces it.

## What "only add" means

Within `v1` we may:

- add an endpoint,
- add an optional parameter,
- add a member to a response,
- add a value to an enum that responses use, an error `code`, or an event type,
- make an endpoint accept more than it did.

We will not remove or rename any of those, change a type, make an optional parameter required, add a required member to a request, or stop accepting a value we accepted before.

That is why every page tells you to **ignore members you do not know**, and to treat an unknown enum value or error `code` as "something new" and not as a crash.

## How it is enforced

The OpenAPI document is committed to the repository (`packages/api/src/openapi.snapshot.json`). A test compares it with the document the code produces and fails if the change is not additive. It lists a removed operation, response member or status, a changed type, a removed or newly required request member or parameter, and a removed enum value a client may send.

```
Not additive. v1 only adds.
  - GET /repos/{owner}/{repo}/issues/{number}: response member title removed
```

A change to the API is therefore a change to that file in the same pull request, so the contract difference is in the diff for a reviewer to read. `bun scripts/api-snapshot.ts` regenerates it and refuses to when the change is not additive.

## Versions by date

`v1` in the path changes rarely. Behaviour that could surprise a client is named by date and chosen with a header:

```http
Sx-Version: 2026-11-07
```

- Every response carries `Sx-Version`, so you can see what answered.
- Omit the header and you get the current version. When there is a second one, a token will be pinned to the version current on the day it was created, so it does not change under you, and the header will override that.
- Send a version we do not support and you get `400 unsupported_version`, with the list in the body and in `GET /v1`.
- A new version means a behaviour change, not a removal. Fields and endpoints are not versioned, they are added.

Today there is one version, `2026-11-07`.

## Deprecation

When we do retire something, which we avoid, the order is:

1. The OpenAPI operation or member is marked `deprecated`, and responses carry `Deprecation` and `Sunset` headers. (Nothing is deprecated yet, so these are not sent yet.)
2. It keeps working for at least 24 months after the replacement ships.
3. It is announced in the changelog and by email to the owners of tokens that used it in the last 90 days.

We name the replacement every time. These rules are our commitment from the hosted launch; the preview has not made a breaking change because it has not had a release.

## Outside the promise

Experimental things are marked `x-sx-experimental` in the OpenAPI document and may change without notice. There are none today. Sample data, the contents of `hint` and `detail` text, and the order of members in an object are not part of the contract. The error `code`, the `status`, the shape of `requirements` and everything in [the reference](/docs/api/reference/changes) are.
